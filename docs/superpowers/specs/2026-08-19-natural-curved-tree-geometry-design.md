# 自然弯曲树木几何设计

## 背景

当前树木已经使用三次贝塞尔曲线描述主干和树枝的走向，但可见网格由 `THREE.TubeGeometry` 生成。该几何体对整根管道使用固定半径，因此 `SemanticBranch.tipRadius` 没有真正参与渲染。结果是主干和树枝像弯曲的圆柱体，末端与分叉连接处还会暴露明显断面。

本次只修正木质结构形态，不改变数据库、七个生活领域、Goal、Activity、叶片、颜色、背景或交互业务规则。

## 目标

- 主树干、一级主树杈和 Goal 细枝都自然弯曲。
- 每根枝条从根部到末端连续渐细。
- 枝条末端收尖，不出现可见的平整圆柱断面。
- 枝条截面带有轻微且稳定的不规则变化，避免工业圆管感。
- 子枝与父枝连接处没有明显裂缝。
- 每根语义枝条仍保持独立的可选中对象，不破坏现有点击、悬停和 Goal 映射。
- 同一份用户数据每次渲染得到相同形态，不产生页面刷新后随机跳变。

## 选定方案

参考 ez-tree 的核心思路，在枝条路径上生成一系列截面环，并把相邻截面环连接为连续三角网格。不同之处是本项目继续使用现有语义树骨架，不引入 ez-tree 的完整递归生成器。

不直接集成 ez-tree，因为它自己的树枝层级生成方式与本项目的 `生活领域 -> Goal -> Activity` 语义关系不同。直接替换会扩大改造范围，并增加交互映射成本。

## 几何生成方式

### 1. 路径采样

每根 `SemanticBranch` 继续使用现有三次贝塞尔控制点。生成网格时，沿曲线均匀取得多个采样点：

- 主干使用较多纵向截面，保证大幅缓弯平滑。
- 一级主树杈使用中等数量截面。
- Goal 细枝使用较少截面，控制几何数量。

每个采样点计算曲线切线，并据此构建稳定的局部截面坐标系，避免截面沿路径突然翻转。

### 2. 连续渐细

每个截面环的半径在 `baseRadius` 与 `tipRadius` 之间进行平滑插值。末端额外快速收尖，使视觉上形成自然枝梢。

主干不会过早变细；一级主树杈和 Goal 细枝的渐细速度依次提高。`tipRadius` 将从未生效的数据字段变成真实的几何参数。

### 3. 不规则截面

每个截面环不使用绝对规则的圆。环上顶点半径加入幅度很小的确定性扰动，形成轻微树皮轮廓变化。

扰动由 `entityId` 和截面位置生成稳定种子，因此不会随刷新改变。扰动幅度受到限制，不能造成树枝凹陷、尖刺或明显折面。

### 4. 弯曲与扭转

树枝总体走向仍由现有贝塞尔控制点决定。自定义网格沿曲线切线平滑旋转截面环，并加入很轻的渐进扭转，使截面变化不会像同一个模具直接拉伸。

本次不会增加风吹动画，也不会让枝条运行时摆动。

### 5. 枝杈连接

子枝的起点沿父枝内部轻微回退或扩大首个截面，让子枝根部嵌入父枝表面，遮住两者之间的缝隙。

各语义枝条仍生成独立 Mesh，而不是合并成一个 Mesh。这样可以继续通过 `entityType`、`entityId` 和 `goalId` 识别用户点击的是哪一个领域或 Goal。

### 6. 枝梢封口

最后一个截面收缩到接近零的半径，并使用一个末端顶点连接最后一圈顶点。这样枝梢是自然尖端，不显示平整的圆形盖面。

主干底部保留不可见或贴近地面的封口，防止从低角度看到内部空洞。

## 参数层级

| 层级 | 纵向截面 | 径向顶点 | 弯曲表现 | 渐细表现 | 截面扰动 |
| --- | ---: | ---: | --- | --- | --- |
| 主树干 | 高 | 10–12 | 缓慢、厚重 | 前缓后快 | 轻微 |
| 一级主树杈 | 中 | 8–10 | 自然外伸 | 持续渐细 | 轻微至中等 |
| Goal 细枝 | 中低 | 6–8 | 更灵活 | 较快收尖 | 中等但受限 |

具体数值集中放在树形参数层，不散落在 Three.js 网格构建函数中，以便以后根据用户数据调整树形。

## 代码边界

- `src/domain/semantic-tree-skeleton.ts`
  - 继续负责生成语义树骨架和稳定形态参数。
  - 补充几何所需的截面、渐细和扰动参数，或提供可由层级推导的信息。
- `src/components/growth-tree-semantic-geometry.ts`
  - 新增或调用自定义枝条 `BufferGeometry` 构建逻辑。
  - 替换当前固定半径的 `TubeGeometry`。
  - 保留现有材质颜色和 Mesh 交互元数据。
- 可新增一个聚焦于纯几何算法的文件，例如 `src/components/growth-tree-branch-geometry.ts`，避免材质、叶片和网格数学混在同一文件。
- `tests/growth-tree-semantic-geometry.test.ts` 及相关新测试
  - 验证渐细、收尖、稳定性和交互元数据。

## 数据流

```text
数据库聚合数据
  -> TreeRecipe（树的成长参数）
  -> SemanticTreeSkeleton（语义枝条 + 曲线路径 + 半径参数）
  -> 自定义枝条 BufferGeometry（截面环 + 渐细 + 扰动）
  -> 独立 Mesh（保留领域/Goal 选择信息）
  -> Three.js 场景
```

## 异常处理

- 曲线长度过短时仍至少生成两个有效截面，避免空几何。
- 半径限制为正数，防止负半径或退化三角形。
- 曲线切线接近参考轴时切换备用轴，避免局部坐标系计算失败。
- 参数不是有限数字时尽早抛出明确错误，避免场景中出现 `NaN` 顶点。

## 验证标准

- 自动测试确认枝条起点平均半径大于末端平均半径。
- 自动测试确认枝梢只有收尖顶点，不存在可见的大面积平盖。
- 自动测试确认相同输入生成完全相同的顶点数据。
- 自动测试确认 Mesh 仍包含正确的 `entityType`、`entityId` 和 `goalId`。
- TypeScript 类型检查通过。
- 本地页面人工检查主干、七个一级主树杈和 Goal 细枝都不再呈现等粗圆柱形态，并检查常用观察角度下没有明显连接裂缝。

## 本次不包含

- 不修改树叶形状、密度或颜色。
- 不修改群山、湖泊、天空、雾或 UI。
- 不加入树皮贴图或 GLB 模型。
- 不改变数据库结构或树的数据映射。
- 不加入生长动画或风吹动画。
