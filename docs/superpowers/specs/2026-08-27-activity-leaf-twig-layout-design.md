# Activity 叶片与细枝布局设计

## 背景

当前实现为每个 Activity 同时生成一套细枝、叶柄和叶片。大量 Activity 属于同一个 Goal 时，这些结构缺少共享的排列层级，容易从接近的位置、以接近的方向重叠，最终看起来像一本合拢或翻开的书。

目标是改成符合树木结构的三级关系：Goal 二级枝干长出多条细枝，Activity 叶片沿细枝左右近似对称分布。细枝只是前端布局结构，不增加数据库实体。

## 数据语义

- 一个 Goal 对应一条二级枝干。
- 一个 Activity 仍严格对应一片可交互叶片。
- 同一个 Goal 下的 Activity 共同使用该 Goal 枝干长出的细枝。
- 每条细枝最多承载 20 片 Activity 叶片。
- 当前细枝满 20 片后，下一个 Activity 才触发一条新细枝。
- 不创建装饰性叶片，叶片总数必须等于可见 Activity 数量。

## 稳定分组

每个 Goal 内部的 Activity 使用稳定顺序排列：优先按完成时间排列；完成时间相同或缺失时，以 Activity ID 作为最终排序依据。

排序后按每组最多 20 个 Activity 依次切分：

- 1–20：第一条细枝。
- 21–40：第二条细枝。
- 41–60：第三条细枝。

使用顺序装满策略，不在新增 Activity 后重新平均分配旧叶片，避免已经形成的树形大范围跳动。

## 细枝布局

每组 Activity 生成一条独立细枝。细枝起点采用稳定的分段随机算法，沿所属 Goal 二级枝干由内向外分布，并遵循以下约束：

- 只使用二级枝干曲线进度 `0.25–0.9`，避开粗壮根部与过细末端。
- 根据细枝总数等分可用区间，每条细枝只能在自己的区间内进行小幅随机偏移。
- 相邻细枝的曲线进度差至少为 `0.12`；不足时向各自区间中心修正。
- 不同细枝不能从同一个节点长出，也不能集中在二级枝干的一小段内。
- 生长方向按左、前、右、后四个扇区轮换，再加入小幅稳定角度扰动。
- 使用 Activity/Goal ID 派生的小幅稳定扰动，避免机械式等距排列。
- 扰动必须是确定性的，相同数据刷新后保持相同形态。
- 细枝采用统一的细长半径，不在末端分叉，不产生刷子状末端。
- 细枝应从二级枝干表面自然接出，不能插入其他枝干。

## 叶片布局

采用已确认的 B 方案：错位近似对生。

- 叶片沿细枝从根部向末端依次生长。
- 细枝左右两侧都有叶片，整体接近对称。
- 左右叶片的节点沿细枝方向略微错开，避免严格成对形成“书页”。
- 每片叶子加入小幅、稳定的绕枝旋转，使叶片不全部共面。
- 叶片顺着细枝向外展开，并带轻微向下倾斜以体现重力。
- 叶柄只负责短距离连接叶片与细枝，不能让叶片悬空。
- 一条未满的细枝只渲染已有 Activity 叶片，不生成占位或装饰叶片。

## 交互

细枝没有业务交互语义。Activity 叶片继续通过 InstancedMesh 渲染，并保持实例索引到 Activity 的一一映射：

- 悬停叶片时显示对应 Activity 的悬停状态。
- 点击叶片时选中对应 Activity。
- 调整空间布局不能改变 Activity 目标解析逻辑。

## 代码边界

预期将“按 Goal 分组并生成共享细枝/叶片位置”的逻辑放在语义树骨架或树配方层；Three.js 几何层只消费计算好的结构并批量创建细枝与叶片，不在渲染阶段重新决定业务分组。

主要涉及：

- `src/domain/semantic-tree-skeleton.ts`：生成按 Goal 分组的细枝和 Activity 叶片锚点。
- `src/components/growth-tree-semantic-geometry.ts`：批量生成细枝几何与叶片实例。
- `src/components/RealisticGrowthTree.tsx`：保持图层装配和 Activity 交互映射。
- 对应单元测试：验证容量、分布、稳定性、数量和交互映射。

## 验收标准

- 同一 Goal 下 20 个 Activity 只生成一条细枝。
- 第 21 个 Activity 生成第二条细枝。
- 任意细枝不超过 20 片叶子。
- 每条具有至少两片叶子的细枝，其左右两侧均有叶片。
- 叶片存在非零、受限的绕枝角度差异，不会全部共面。
- 不同细枝的连接点不重叠。
- 同一 Goal 的细枝连接点覆盖二级枝干的多个分段，而不是聚集在同一区域。
- 同一 Goal 的细枝生长方向覆盖多个扇区，而不是全部朝向同一侧。
- 叶片数与可见 Activity 数严格相等。
- 相同输入重复生成的细枝与叶片位置完全稳定。
- 原有 Activity 悬停和点击定位保持有效。
- 类型检查及完整测试集通过。

## 非目标

- 不修改数据库结构。
- 不改变 Goal、Activity 或 Task 的业务含义。
- 不引入装饰性叶片。
- 不为细枝增加点击交互。
- 不修改水体、岛屿、天气或相机效果。
